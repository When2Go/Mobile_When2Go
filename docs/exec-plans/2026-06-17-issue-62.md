## 배경 / 방향 정정

이슈 본문 완료 기준은 "초록 핀 제거 → SDK 내장 파란 점만 남김"이었으나,
실제 확인 결과 **정확도가 반대**였다.

| 표시 | 좌표 소스 | 정확도 |
|---|---|---|
| 초록 핀 (`NaverMapMarkerOverlay`) | `useCurrentLocation`의 `lat/lng` (expo-location) | 정확 |
| 파란 점 (`Follow` 모드 내장 오버레이) | 네이버 SDK 내부 GPS | 부정확 |

따라서 **버리는 쪽을 반대로** 한다. SDK 내부 위치 시스템으로 그리는 파란 점을 제거하고,
정확한 `useCurrentLocation` 좌표를 **일반 마커 오버레이**(`NaverMapMarkerOverlay`)로 그린다.
화면 결과는 "파란 점 하나"로 동일하되 좌표 소스가 정확한 쪽이 된다.

### 검증 과정 메모 (방법 1차 시도 → 폐기)

처음엔 `NaverMapView`의 `locationOverlay` prop에 `position`을 직접 지정하면 될 거라 봤으나,
시뮬레이터 확인 결과 **여전히 어긋났다**(초기에 벗어나 찍히고 줌인할수록 정위치로 수렴 — 기존 파란 점과 동일 증상).
`locationOverlay`와 `setLocationTrackingMode(Follow)`는 모두 SDK 내부 위치 시스템(OS GPS)이 우선해 우리 `position`을 무시한다.
→ SDK 위치 시스템을 거치지 않는 **일반 마커 오버레이 + 커스텀 뷰**로 최종 전환.

## 목표

- 정확한 현재 위치(`useCurrentLocation` 좌표)에 표준 파란 점 하나만 표시
- 줌 변경 시 어긋남 없음 (점·카메라 모두 동일 좌표 소스)
- 권한 미허용 폴백(서울시청 중심 + 캡션) 동작 유지
