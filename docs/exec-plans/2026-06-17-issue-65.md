## ⚠️ 설계 변경 — 로컬 저장 폐기, 백엔드 Trip API 사용

초안은 로컬 AsyncStorage(`scheduleStore`)였으나, 백엔드에 `/api/trips`가 이미 완성돼 있고
**FCM 푸시 트리거의 전제(백엔드가 trip을 알아야 출발 알림 발송)** 때문에 로컬 저장은 틀린 선택.
→ Trip API 연동으로 전환. `scheduleStore`/`scheduleDate` 로컬 설계 폐기.

## 백엔드 API (docs/references/api-schema.md §2)

| 메서드 | 엔드포인트 | 용도 |
|--------|-----------|------|
| POST | `/api/trips` | 여정 생성 |
| GET | `/api/trips?status=&date=` | 목록 (status·date **둘 다 필수**) |
| GET | `/api/trips/{tripId}` | 상세 |
| DELETE | `/api/trips/{tripId}` | 삭제 |

- 인증: `X-Device-Id` 헤더 — **이미 axios 인터셉터(`interceptors/auth.ts`)가 자동 주입**. 추가 작업 불필요.
- 에러: `interceptors/error.ts`가 `ApiFailure`로 정규화. (route 클라이언트와 동일 패턴)
- `TripStatus` = `PENDING` / `SCHEDULED` / `COMPLETED` (3개. `IN_PROGRESS`/`CANCELLED` 제거됨)

## 데이터 갭 검증 결과 (POST /api/trips 필수 필드)

| 필드 | 출처 | 상태 |
|------|------|------|
| `originName` | "현재 위치" 리터럴 | 전송 시 채움 |
| `originLat`/`originLng` | `routeDraftStore.fromCoords` (setup GPS) | ✅ |
| `destName` | setup `destination` 파라미터 | result까지 전달 필요 → store에 `toName` 추가 |
| `destLat`/`destLng` | `routeDraftStore.toCoords` (search 선택 시) | ✅ (확정 시점 항상 존재) |
| `arrivalTime` (ISO 8601) | setup `arrivalTime` 파라미터 `"YYYY-MM-DD HH:mm"` | ISO 변환 유틸 필요 |
| `bufferMinutes` | `result`의 `safetyBufferMin` (settings + override) | ✅ |
| `durationSeconds` | `selectedRoute` | **갭**: `RouteDisplayItem`에 미보유. `normalizeRoute`가 계산은 하나 버림 → 필드 추가 |

## 구조적 제약 — 달력 마커 (결정 필요)

GET `/api/trips`는 `status`·`date`가 **둘 다 필수**(단일 날짜). 월 범위 조회 API 없음.
→ "그 달에 일정이 있는 날" 마커를 그리려면 날짜별로 여러 번 호출해야 함.
백엔드는 별도 레포라 프론트에서 월 조회 API를 추가할 수 없음.

**채택안: (B) MVP — 선택 날짜 목록만 조회.** 월 전체 마커는 후속 이슈로 분리.
- 날짜 선택 시 그 날짜만 `GET /api/trips?status=SCHEDULED&date=...` 조회.
- `markedDays`는 빈 배열로 두거나 "현재 로드된 선택일에 일정 있으면 그 날만" 정도로 최소화.
- `MOCK_MARKED_OFFSETS_FROM_TODAY` 기반 mock 마커 제거.

## TripListResponse → 화면 매핑

`GET /api/trips` 항목: `tripId`, `originName`, `destName`, `arrivalTime`(ISO), `finalDepartureTime`(ISO, nullable), `status`.

화면 `ScheduleItem` 매핑:
- `id` ← `tripId`
- `title`/`destination`/`to` ← `destName`, `from` ← `originName`
- `arrivalTime`(표시) ← `arrivalTime` ISO → 한국어 시각
- `departureTime`(표시) ← `finalDepartureTime` ISO → 한국어 시각 (null이면 "-")
- `status` ← `TripStatus` 매핑: `PENDING` → '예정', `SCHEDULED` → '확정'(출발 시각이 확정된 상태), `COMPLETED` → '완료'. (현재 진행 중 개념은 백엔드에 없어 isActive는 항상 false)
- `route` ← `originName → destName` (목록엔 경로 단계 없음)
- `updatedAt` ← null (목록 미제공), `isActive` ← false
- `date` ← `arrivalTime`의 날짜 부분
