## 목표

`TimeWheelPicker`의 `WheelColumn`이 `ScrollView + options.map`으로 휠 항목(period 2 + hour 12 + minute 60 ≈ 74개)을 전부 마운트하는 구조를, 화면에 보이는 항목만 렌더하는 가상화(windowing)로 교체한다. 저사양 Android에서 60개 분 휠 드래그 시 페이드 프레임 드랍을 완화한다. 기능 동작·시각은 완전히 동일하게 보존한다.

## 설계

`WheelColumn` 내부의 `Animated.ScrollView` + `options.map` → `Animated.FlatList` 기반으로 교체.

보존(절대 변경 금지):
- `Props`(period/hour/minute + onXxxChange) 인터페이스
- `wheelPicker.ts`의 `clampIndex`/`offsetToIndex`/`indexToOffset` 수식 (offset = index × itemHeight)
- snapToInterval / decelerationRate='fast' / scrollEventThrottle
- `scrollY` 공유값 + `WheelItem`의 거리 기반 opacity/scale 페이드 워크릿
- 외부 prop → index scrollTo 동기화, `programmaticIndexRef` 피드백 루프 가드, `didMountRef` 마운트 가드
- 이중 발화 가드(`isMomentumScrollRef`, onScrollEndDrag rAF 폴백), 탭 폴백
- `NativeViewGestureHandler disallowInterruption` 래핑
- 중앙 강조 박스 / z-order / 안내 텍스트

FlatList 전환 세부:
- 스페이서: `contentContainerStyle paddingVertical` 대신 `ListHeaderComponent`/`ListFooterComponent`(각 height `SPACER_HEIGHT`)로 이동. 이유: `getItemLayout` offset과 실제 레이아웃을 정확히 일치시켜 FlatList의 렌더 윈도우 판정이 어긋나지 않게 함.
- `getItemLayout={(_, index) => ({ length: WHEEL_ITEM_HEIGHT, offset: SPACER_HEIGHT + index * WHEEL_ITEM_HEIGHT, index })}` — 헤더(스페이서) 높이 포함. 고정 높이라 정확 → 초기 중앙 위치 렌더 윈도우 즉시 계산(초기 blank flash 방지) + 윈도잉 정밀.
- 초기 위치: `contentOffset={{ x: 0, y: indexToOffset(selectedIndex, WHEEL_ITEM_HEIGHT) }}` 유지(센터링 수식 불변 — 헤더 추가는 스크롤 offset 0 = 콘텐츠 top이라 영향 없음).
- 프로그램적 스크롤: `scrollRef.current?.scrollTo(...)` → `scrollRef.current?.scrollToOffset({ offset: indexToOffset(index), animated })`.
- `data={options}`, `keyExtractor={(item) => format(item)}`(값 기준 안정 key → 워크릿/항목 재활용 충돌 방지), `renderItem`이 데이터 index로 `WheelItem` 렌더.
- 윈도우 튜닝: `initialNumToRender`, `maxToRenderPerBatch`, `windowSize`(작게). 페이드 구간(FADE_DISTANCE = side+1 = 3)이 항상 마운트되도록 `windowSize`로 가시 영역보다 넉넉히 확보. 상수로 선언(매직넘버 금지). `removeClippedSubviews`는 **미적용** — reanimated 워크릿이 붙은 셀을 클립할 때 페이드/터치가 깨지는 알려진 문제가 있어 의도적으로 제외.
- 모든 스크롤 핸들러(onScroll/BeginDrag/MomentumBegin/EndDrag/MomentumEnd)는 FlatList에 그대로 전달.

### BottomSheetScrollView 중첩(QA 1차 [CRITICAL] 대응)

`RepeatEditModal`은 `scrollable`(=`BottomSheetScrollView`) 안에서 휠을 렌더한다. FlatList(VirtualizedList)를 세로 ScrollView 안에 중첩하면 RN이 `__DEV__`에서 "VirtualizedLists should never be nested inside plain ScrollViews" `console.error`를 띄운다(`VirtualizedList.js:1150`, `ScrollView.Context.Consumer` 기준).

- **윈도잉 자체는 정상**: 휠 FlatList는 고정 높이(`WHEEL_HEIGHT=220`) 컨테이너 안이라 뷰포트를 220px로 측정 → 가상화 동작. 경고가 우려하는 "unbounded height로 전체 렌더"에 해당하지 않음.
- **경고만 제거**: 휠 FlatList 서브트리를 `<ScrollView.Context.Provider value={null}>`로 감싸 orientation context를 리셋. 휠은 시트 스크롤에 기여하지 않는 독립 고정 높이 스크롤이라 의미상 정확. `NativeViewGestureHandler`의 직접 자식은 FlatList로 유지(제스처 독점 보존). `ScrollView.Context`는 VirtualizedList가 소비하는 동일 context 인스턴스(둘 다 `react-native`의 단일 ScrollView 모듈)임을 소스로 확인.
