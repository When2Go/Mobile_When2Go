# Issue #47 — TimeWheelPicker 휠 가상화(windowing)

- 원본 이슈: https://github.com/When2Go/Mobile_When2Go/issues/47

## 목표

`TimeWheelPicker`의 `WheelColumn`이 `ScrollView + options.map`으로 휠 항목(period 2 + hour 12 + minute 60 ≈ 74개)을 전부 마운트하는 구조를, 화면에 보이는 항목만 렌더하는 가상화(windowing)로 교체한다. 저사양 Android에서 60개 분 휠 드래그 시 페이드 프레임 드랍을 완화한다. 기능 동작·시각은 완전히 동일하게 보존한다.

## 관련 파일

- `src/components/setup/TimeWheelPicker.tsx` — **주 변경 대상** (WheelColumn 렌더 구조)
- `src/utils/wheelPicker.ts` — offset↔index 순수 계산. **변경 없음** (보존)
- `src/constants/setup.ts` — 레이아웃 상수. **변경 없음**
- 사용처(인터페이스 보존 확인용, 변경 없음):
  - `src/components/setup/ArrivalTimePicker.tsx`
  - `src/components/repeat/RepeatEditModal.tsx` (좁은 박스 — 레이아웃 영향 주의)

## 설계 변경 이력

- **초안**: `Animated.FlatList` 기반 네이티브 윈도잉. → iOS 실기기에서 **초기 렌더 버그** 발견: `contentOffset`(가운데 정렬용 초기 스크롤)이 FlatList의 렌더 윈도우 판정에 반영되지 않아, 첫 화면에 선택값 1칸만/분은 빈칸으로 뜨고 드래그해야 채워짐. `initialScrollIndex`로는 "맨 위 붙이기"라 가운데 정렬과 양립 불가(위쪽 이웃 칸이 첫 페인트에 빈칸). FlatList로는 "가운데 정렬 + 첫 화면 이웃 표시"가 깔끔히 안 됨.
- **확정**: `Animated.ScrollView`로 되돌리고 **가시 범위 슬라이싱**으로 윈도잉. 어떤 칸을 그릴지 직접 제어(선택값 ±N) → 첫 렌더부터 정상. ScrollView는 VirtualizedList가 아니라 1차 [CRITICAL](BottomSheet 중첩 경고)도 자동 해소(`ScrollView.Context` 우회 불필요).

## 설계 (확정: ScrollView + 슬라이싱)

`WheelColumn` 내부의 `options.map`(전체 마운트) → 가시 범위 슬라이싱으로 교체.

- `Animated.ScrollView` 유지(원래 동작하던 `contentOffset` 초기 위치·snap·제스처 그대로).
- 항목을 **절대 위치**(top = `SPACER_HEIGHT + index*ITEM_HEIGHT`)로 깔고, 콘텐츠 컨테이너 높이를 `length*ITEM_HEIGHT + 2*SPACER`로 고정 → 안 그린 칸이 있어도 스크롤 범위·snap 불변.
- `renderCenter` state: `useAnimatedReaction`으로 `scrollY`를 관찰해 **정수 칸이 바뀔 때만** `runOnJS`로 갱신(매 프레임 setState 아님). 초기값 = `selectedIndex` → 첫 렌더부터 선택값·이웃 정상 표시.
- 중앙 `±WHEEL_RENDER_SIDE_COUNT`(=8, 최대 17칸)만 렌더 → 분 60칸 중 ~17칸만 마운트, 매 프레임 평가 워크릿 수 감소.
- `contentOffset`는 `selectedIndex`에만 의존(슬라이싱 state와 분리) → 슬라이싱 re-render가 잦아도 값이 불변이라 스크롤 점프 없음.

보존(절대 변경 금지):
- `Props`(period/hour/minute + onXxxChange) 인터페이스
- `wheelPicker.ts`의 `clampIndex`/`offsetToIndex`/`indexToOffset` 수식 (offset = index × itemHeight)
- snapToInterval / decelerationRate='fast' / scrollEventThrottle
- `scrollY` 공유값 + `WheelItem`의 거리 기반 opacity/scale 페이드 워크릿
- 외부 prop → index scrollTo 동기화, `programmaticIndexRef` 피드백 루프 가드, `didMountRef` 마운트 가드
- 이중 발화 가드(`isMomentumScrollRef`, onScrollEndDrag rAF 폴백), 탭 폴백
- `NativeViewGestureHandler disallowInterruption` 래핑
- 중앙 강조 박스 / z-order / 안내 텍스트

기타:
- `removeClippedSubviews` 등 FlatList 전용 튜닝은 해당 없음(ScrollView 사용).
- 1차 [CRITICAL](BottomSheet 중첩 경고)은 ScrollView 복귀로 자연 해소 — VirtualizedList가 아니라 경고 조건 자체가 성립하지 않음.
