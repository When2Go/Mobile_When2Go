- **PRD ID**: F-U02 (즐겨찾기)
- **작업 유형**: feature + refactor (mock 제거 → 로컬 영속화)

## 배경 / 범위 조정

이슈 #17 원안은 "즐겨찾기 + 반복 예약 CRUD를 **실 API**로 교체"였습니다.
현 시점 기준으로 두 가지가 달라졌습니다.

1. **반복 예약(RepeatReservation)** 은 이미 별도로 처리됨 (커밋 `4cea987 repeat.tsx API 연동`). → 이번 작업 범위에서 제외.
2. **즐겨찾기(Routes)** 는 백엔드 API가 아직 없습니다. → API 연동 대신 **로컬 영속 저장(AsyncStorage)** 으로 구현.

따라서 이번 작업은 **`app/routes.tsx` 경로 관리 페이지를 더미 제거 + 로컬 저장으로 구체화**하는 것에 한정합니다.

### 사용자 결정 사항 (2026-06-19)

- **통합 범위**: 경로 관리 페이지(`app/routes.tsx`)만. 홈 '자주 가는 곳'(`FavoriteRoutes`) 통합은 **별도 이슈로 분리**.
- **좌표 저장**: 경로에 `lat/lng` 좌표도 함께 저장. setup 진입 시 재검색 없이 바로 쓰도록 구체화.

## 목표

- 더미 데이터(`MOCK_ROUTES`) 완전 제거.
- 경로 CRUD가 **앱 재시작 후에도 유지**되도록 AsyncStorage에 영속화.
- 출발지/목적지 좌표를 경로에 함께 저장 → setup 진입 시 좌표 재사용.

| 파일 | 현재 상태 | 문제 |

**참고 모범 사례**: `src/stores/recentSearchesStore.ts` — zustand + AsyncStorage + `hydrate()` + `_isHydrated` 가드 + `STORAGE_KEYS` 패턴. 이 구조를 그대로 따릅니다.

## 설계

### 1. 타입 확장 — `src/types/routes.types.ts`

```ts
export interface Coords { lat: number; lng: number; }

export interface RouteItem {
  id: string;               // number → string (영속 환경 안전한 ID. 아래 ID 정책 참조)
  name: string;
  from: string;
  to: string;
  frequency: string;
  fromCoords?: Coords;      // 선택: 검색으로 위치 선택 시 채워짐
  toCoords?: Coords;
}
export type RouteFormData = Omit<RouteItem, 'id'>;
```

- **ID 정책**: 모듈 `nextId` 변수는 영속 환경에서 충돌/리셋 위험. 저장된 경로 중 최대값 기반 증가 또는 단순 카운터를 store 내부에서 관리. (`Date.now()`/`Math.random()` 직접 사용은 피하고, store가 보관하는 `_seq` 카운터를 persist에 포함시켜 단조 증가시킴.)
  - `id` 타입을 `number`→`string`으로 바꾸면 `RouteListItem.onDelete(id)` 등 시그니처도 함께 수정.

### 2. 신규 스토어 — `src/stores/routeStore.ts`

`recentSearchesStore` 패턴 복제:

```
state: routes: RouteItem[], _seq: number, _isHydrated: boolean
actions:
  hydrate()                       // AsyncStorage 로드 (앱 시작 시 1회)
  addRoute(form: RouteFormData)   // _seq 증가 → 새 RouteItem push → persist
  updateRoute(id, form)           // map 교체 → persist
  removeRoute(id)                 // filter → persist
```

- `STORAGE_KEYS.ROUTES = '@when2go/routes'` 추가 (`src/constants/storageKeys.ts`).
- persist 페이로드는 `{ routes, _seq }` 형태로 저장(다음 ID 단조 보장).
- 저장/로드 에러는 `__DEV__` warn 으로만 (기존 store와 동일).

### 3. `app/routes.tsx` 리팩터링

- `MOCK_ROUTES`, `nextId`, 로컬 `useState<RouteItem[]>` **제거**.
- `useRouteStore`에서 `routes` 구독 + `addRoute/updateRoute/removeRoute` 사용.
- 앱 루트(`app/_layout.tsx`)에서 `hydrate()` 호출 (기존 store들이 어디서 hydrate되는지 확인 후 동일 위치에 추가).
- `handleSave`: 폼 + `routeDraftStore`의 좌표(`fromCoords/toCoords`)를 합쳐 저장.
- `handleNavigateToSetup`: 목적지 텍스트 + `toCoords`를 `routeDraftStore.setCoords('to', ...)` / `setToName(route.to)`로 주입 후 setup 이동 → 재검색 불필요.

### 4. 좌표 흐름 연결 — `RouteEditModal` ↔ `routeDraftStore`

- 현재 search 복귀 시 텍스트(`pendingLocation`)만 폼에 반영됨. 좌표도 함께 받아 `draftForm.fromCoords/toCoords`에 채우도록 `routes.tsx`의 `useFocusEffect` 핸들러 보강.
- search 화면이 위치 선택 시 좌표를 어디에 싣는지(`pendingLocation`에 coords 포함 여부) 확인 후, 없으면 `pendingLocation`에 coords 추가 또는 `setCoords` 동시 호출로 연결.

### 5. 빈 상태

- `EmptyState`는 그대로 사용 (더미 제거 시 첫 진입은 자연히 빈 목록 → EmptyState 노출). 추가 작업 없음.
